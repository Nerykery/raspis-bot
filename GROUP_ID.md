# Формирование идентификатора группы (groupNumber) для API расписания ТУСУР

Документ описывает, как устроен идентификатор группы, который используется в
API расписания мобильного приложения **ТУСУР Marketplace** (Flutter, `api.tusur.ru`).
Предназначен для передачи другой нейросети/разработчику для интеграции.

---

## 1. Где используется id

Идентификатор группы (`groupNumber`) — это строка вида `746-1`. Она подставляется
в URL напрямую (path-параметр), без дополнительного кодирования.

| Назначение | Метод | URL |
|-----------|-------|-----|
| Расписание занятий группы | GET | `https://api.tusur.ru/api/v1/timetable/lessons/{group}?dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD` |
| Учебные недели (чётность/календарь) | GET | `https://api.tusur.ru/api/v1/timetable/weeks/{group}` |
| Расписание преподавателя (не группа) | GET | `https://api.tusur.ru/api/v1/timetable/lessons/lecturer?dateFrom=..&dateTo=..&name=<Фамилия>` |

Пример:
```
https://api.tusur.ru/api/v1/timetable/lessons/746-1?dateFrom=2026-10-12&dateTo=2026-10-18
```

---

## 2. Откуда берётся id (в самом приложении)

`groupNumber` **не формируется на клиенте** — это поле приходит с сервера в профиле
студента и используется как есть.

- Источник: `GET /api/v1/student/{id}` → объект `ProfileDto`.
- Поле: `groupNumber` (строка, например `"746-1"`).
- Сопутствующие поля профиля: `course`, `faculty`, `facultyFull`, `directionName`,
  `recordBookNumber`, `contingentPersonId`.
- Далее `groupNumber` передаётся в `ScheduleBloc` → `ScheduleRepository.getGroupSchedule(group)`
  → `_ScheduleDataSource.getGroupLessons(group, dateFrom, dateTo)`, где и подставляется в путь.

Важно: `student/{id}` требует авторизации (Bearer token), поэтому получить
`groupNumber` для чужого студента без токена нельзя. Но сам эндпоинт расписания
**публичный** — зная строку группы, можно запросить расписание без авторизации.

---

## 3. Формат идентификатора

```
{числовая часть}-{номер подгруппы}
```

- **Разделитель** — дефис `-` (ASCII, U+002D).
- **Числовая часть** — 3 цифры (например `746`, `716`, `143`, `995`).
- **Номер подгруппы** — 1–2 цифры (`1`, `2`, `10`...). Обычно `1` или `2`.
- Возможен суффикс `топ` между числовой частью и дефисом (см. §4).

Регистр и пробелы значения не имеют для «обычных» групп, но для варианта с `топ`
используется **строчная кириллица**: `716топ-1`.

---

## 4. Варианты (эмпирически проверено)

Проверялись реальными запросами к `api.tusur.ru` (окно 12–18.10.2026).
HTTP `200` = группа существует и отдала данные; `404` = не найдена.

### 4.1. Обычные группы
```
746-1  -> 200
716-1  -> 200
726-1  -> 200
736-1  -> 200
766-1  -> 200
143-4  -> 200
713-1  -> 200
713-2  -> 200
```

### 4.2. Группы с суффиксом `топ`
```
716топ-1 -> 200
716топ-2 -> 200
746топ-1 -> 404   (такой группы нет — проверка отрицательная)
713топ-1 -> 404
```
Схема: `<числа>топ-<подгруппа>` (кириллица «топ», нижний регистр).

### 4.3. Что НЕ является валидным id
```
746     -> 404   (без подгруппы)
746-2   -> 404   (нет такой подгруппы у 746)
746-01  -> 404   (ведущий ноль не принимается)
746-1a  -> 404
746-1м  -> 404
746б-1  -> 404
746-1/1 -> 500   (слэш ломает роутинг)
746-1/  -> 301   (редирект на версию без слэша)
```

---

## 5. Разбор числовой части (наблюдения, не официальная спецификация)

Числовая часть кодирует принадлежность к институту/направлению и курс.
Строгих публичных правил нет — корректнее всего брать значение из профиля.
Тем не менее, наблюдаемая закономерность на выборке:

- **1-я цифра** — институт/факультетский префикс. Проверено с шаблоном `X16-1`:
  ```
  016-1 -> 200
  116-1 -> 200
  516-1 -> 200
  616-1 -> 200
  716-1 -> 200
  216-1/316-1/416-1/816-1/916-1 -> 404
  ```
  Т.е. валидны не все префиксы — набор ограничен существующими институтами.

- **3-я цифра** (младший разряд числовой части) часто связана с курсом.
  Для префикса `71X-1`:
  ```
  713-1 -> 200
  714-1 -> 200
  715-1 -> 200
  716-1 -> 200
  710/711/712/717/718/719-1 -> 404
  ```

> Вывод: **не пытайтесь конструировать id по формуле** — это ненадёжно.
> Единственный корректный источник — поле `groupNumber` из профиля студента
> (`GET /api/v1/student/{id}`), либо строка, введённая/выбранная пользователем.

---

## 6. Проверка валидности id

Так как отдельного эндпоинта «список групп» в API не обнаружено, валидность
определяется по коду ответа:

- `200` + JSON `{"data":[...]}` — группа существует.
- `404` — группы нет.
- `500` (`invalid status code`) — сервер получил некорректный id (например,
  `weeks/<мусор>` или id со слэшем).

Рекомендуется: получить `groupNumber` из профиля и использовать его без изменений.

---

## 7. Формат ответа

### 7.1. `GET /api/v1/timetable/lessons/{group}`

Query:
- `dateFrom` (обязательно) — `YYYY-MM-DD`
- `dateTo` (обязательно) — `YYYY-MM-DD`

Ответ:
```json
{
  "data": [
    {
      "date": "2026-10-12",
      "lessons": [
        {
          "day": 1,
          "number": 3,
          "name": "Физическая культура и спорт",
          "abbr": "ФКиС",
          "kind": "Практика",
          "startTime": "13:15",
          "endTime": "14:50",
          "classroom": "",
          "groups": "716-1, 716-2, 716топ-1, 716топ-2, 726-1, 726-2, 736-1, 746-1, 766-1",
          "lecturers": [
            { "id": 35113, "firstName": "Олеся", "middleName": "Олеговна", "lastName": "..." }
          ]
        }
      ]
    }
  ]
}
```

Поля урока (`LessonDto`): `day`, `number`, `name`, `abbr`, `kind`,
`startTime`, `endTime`, `classroom`, `groups` (строка через запятую),
`lecturers[]` (`id`, `firstName`, `middleName`, `lastName`).

### 7.2. `GET /api/v1/timetable/weeks/{group}`

Ответ (`WeekDto`): `parity` (`odd`/`even`), `startsAt` (`YYYY-MM-DD`),
`timetable` (строка вида `"Э, Э, Э, К, К, К, В"`), `weekId` (int),
`weekNumber` (int).

Пример:
```json
{ "data": [
  { "parity": "odd",  "startsAt": "2027-02-01", "timetable": "Э, Э, Э, Э, Э, Э, В", "weekId": 861, "weekNumber": 23 },
  { "parity": "even", "startsAt": "2027-01-25", "timetable": "Э, Э, Э, Э, Э, Э, В", "weekId": 860, "weekNumber": 22 }
]}
```

## 8. Примеры запросов

```bash
# Расписание группы 746-1
curl "https://api.tusur.ru/api/v1/timetable/lessons/746-1?dateFrom=2026-10-12&dateTo=2026-10-18"

# Учебные недели группы 746-1
curl "https://api.tusur.ru/api/v1/timetable/weeks/746-1"

# Расписание преподавателя по фамилии
curl "https://api.tusur.ru/api/v1/timetable/lessons/lecturer?dateFrom=2026-10-12&dateTo=2026-10-18&name=Иванов"
```

Авторизация для этих трёх запросов **не требуется**.

---

## 9. Краткая шпаргалка

- id группы = `groupNumber` из `GET /api/v1/student/{id}` (Bearer), формат `NNN-N`
  (напр. `746-1`), возможен вариант `NNNтоп-N` (напр. `716топ-1`).
- Подставляется в путь: `.../timetable/lessons/{group}` и `.../timetable/weeks/{group}`.
- `dateFrom`/`dateTo` — обязательные query-параметры в формате `YYYY-MM-DD`.
- Эндпоинты публичные, авторизация не нужна.
- Не конструировать id по формуле — брать готовое значение.
